# Technical Plan

## Architecture
Static front-end mobile game with a deterministic release-packaging step: native ES modules, HTML/CSS, original SVG pixel sprites, Canvas 2D Tower, and lazy-loaded CC0 sampled Wrap/Sorting/Sleigh instruments and original Web Audio accompaniment. One vendored MIT QR encoder; no server, accounts, analytics, cookies, CDN fonts, or network saves. GitHub Pages serves `main:/docs`: an unannounced public review preview, not the campaign launch.

## Key Components
- `docs/index.html`: game entry; game title and copy come from the content module.
- `docs/game/content.js`: **all player-facing copy and character names**, preset identities, game release dates, difficulty settings, placeholder finale code/message.
- `docs/game/engine.js`: save schema/validation, date gates, grading/timing, stacking collision rules; no DOM.
- `docs/game/sorting.js`: pure endless sorting engine; stages, overrides, queue, scoring and medals.
- `docs/game/sorting-ui.js`: portrait sorting room, cards, pause and pointer/number-key input.
- `docs/game/sorting-feedback.js`: immediate sampled mid/high sack cues, generated comic effects, combo/stage echoes and tiered results flourish.
- `docs/game/sorting-music.js`: dynamically imported complete public-domain carol score, three verse textures and a separate duckable sampled band sharing the existing audio bank/context.
- `docs/game/rhythm.js`: pure lane/timing judgement, penalties, combos and customer grades.
- `docs/game/music.js`: lazy CC0 sample bank, sampled lane instruments, original bass/chord/kit/pad backing and output-latency-aware scheduling. `docs/game/audio/` holds the bank, pinned sources, full CC0 licence and reachable credits.
- `docs/game/app.js`: guarded hash navigation, screens, input, saves, review controls, game loops, audio lifecycle, pause/resume.
- `docs/game/art.js`: original integer-grid SVG sprites, hub houses, gift. No licensed assets.
- `docs/game/treasure.js`: pure shared reward/collection engine, idempotent external awards by source/key, box odds and Rare guarantee, set rewards and layer hosts.
- `docs/game/treasure-ui.js` / `treasure-art.js`: book, helpers, outfit slots, original SVG card and outfit art, Home Screen and save safeguards.
- `docs/game/save-code.js`: compact dictionary save format, TV1 version and seven-character checksum; local QR through vendored qrcode-generator.
- `docs/game/style.css`: portrait-first UI, pixel presentation, reduced motion.
- `docs/art-direction/index.html`: preserved comparison gallery.
- `docs/art-direction/assets/`: nine original portrait PNG screen mock-ups.
- `docs/art-direction/prompts.md`: common character/constraint brief plus each image's style and screen brief, generated with the built-in image_gen tool.
- `docs/art-direction/style-sheet.html`: selected cozy pixel palette, outline/grid rules, helper + two customers, supporting cast, production limits.
- `tests/engine.test.js`: date boundaries, save resilience, timing, stacking checks.
- `tests/browser/adventure.spec.js`: full game journeys, review/date guards, persistence, mobile/tablet layouts.

## Dates and availability
`C.episodes` in content.js defines four ordered game slots: Wrap Nov 13, Sorting Office Nov 20, Tower Nov 27, Sleigh-Cart Run Dec 4, all at Toronto midnight (05:00 UTC). Open games stay open. Locked and unbuilt hub cards/house links are disabled, dimmed and have no card arrow; blocked direct game URLs return to the hub. Each slot’s cast selects its distinct card host. Open cards show “Not played yet” until a completed run is recorded (including below-medal runs); then they show the saved best. Unbuilt slots stay coming soon even in review mode. Finale remains Dec 12, 2026 at 4 PM Toronto (`2026-12-12T21:00:00Z`). Countdown targets the next slot date, then finale.

`trusted-clock.js` fetches a unique same-origin HEAD path with cache:no-store (query strings alone do not bypass every CDN). An intentional missing path returns 404 with the host’s current Date header; no response body is downloaded. It validates the response Date and rejects positive Age. No third-party requests or device wall clock. performance.now advances from the server anchor; visibility return and online events recheck the host. Hiding/offline freezes the last observed verified instant. Reloads retain that instant, but offline elapsed time cannot open future gates. All game and finale date checks use this clock. A failed initial check leaves date gates closed with a connection note. Static frontend checks deter device-date changes, but developer tools can modify code/storage; withholding game code until release would require a different publication system.

`docs/sw.js` is generated from `scripts/sw.js`. It caches every file in its immutable release, including audio and sorting-music.js, verifies SHA-256 before activation, and uses exact URL matches. Audio decoding and playback remain lazy. Host clock and update probes bypass worker handling. Installation reuses and re-verifies files already cached by update preparation, avoiding a second full transfer. Prior local release caches are retained for other open tabs; a running-build message prunes them only with one client and a matching worker build. Offline root navigation serves the worker’s complete cached release.

## Game rules
- Wrap: 3 customers × 41–57-second public-domain carols, plus a falling-object lead-in. Four lanes in Fold/Tape/Ribbon/Bow order. Easy uses Fold/Tape at least 1500 ms apart, Tunie uses four lanes, and Rapper speeds up the same melody with occasional two-lane octave pairs. Quarter-note beats are 750 ms (Easy/Tunie) or 650 ms (Rapper); melody rhythms include half beats. Windows are ±360/300/250 ms; perfect windows ±145/120/100 ms. Pointerdown handles each thumb independently; desktop D/F/J/K and Left/Down/Up/Right keys mirror the buttons. Wrong lanes consume one nearby object; empty/wrong taps break combos and deduct score and accuracy. Missing never ends the song. Free instrument play leads to four slow, retrying guided shapes.
- Sound: successful Wrap taps play chart MIDI pitches through real recorded marimba (Fold), pizzicato strings (Tape), harp (Ribbon), and glockenspiel (Bow). Missed chart notes stay silent. Easy quietly fills only uncharted notes; Tunie/Rapper have no automatic melody. Deck the Halls, O Christmas Tree and Joy to the World use public-domain melodies, with our own sampled bass/chord accompaniment and generated kit/warm pad. O Christmas Tree is arranged in common time. The 642,224-byte PCM bank is fetched/decoded only on entering Wrap, Sorting Office or Sleigh-Cart Run (including direct practice/play links), with a friendly non-blocking loading/failure message. Bank failure leaves visual play available. Sound credits/source paths/licence are in game/audio/. Other game cues retain original synthesis. Wrap samples run through conservative gains and a compressor; melody sits above backing. Visual and judgement clocks share performance.now(). Backing/fill/count-in attacks compensate measured getOutputTimestamp latency or baseLatency + outputLatency. Hit sounds start immediately on pointerdown; unavoidable hardware/Bluetooth delay still requires physical-phone assessment. Three count-in clicks/visible numbers fit inside existing travel lead-in, ending at time zero. Audio unlocks on gestures and stops on pause/navigation/backgrounding; resume resets both backing and fill cursors so cancelled scheduled notes can be rescheduled. Sound is optional; all gameplay is visual. Wrap/Tower pause on hiding and require explicit resume.
- Every finished non-practice round/run queues a Basic/Bronze/Silver/Gold box from its best medal; a personal best adds a second matching box. Wrap B/A/S = Bronze/Silver/Gold; a C-only round earns Basic without layer 1. Tower Bronze/Silver/Gold = 12/25/40 stacked gifts. Sleigh uses its existing medals; Sorting keeps its existing finish-to-layer rule pending sorting-one-ramp. Each medal unlocks its outfit and lower tiers; won layers add their hosts. Finale code alone awards Opening Night. Replays can improve bests and earn further boxes.
- Four six-card street sets unlock on the episode dates; boxes contain only open sets (Candy welcome pool before launch). Host cards never drop. Five Mythicals: Champion (1% Gold only, with crown), Collector (all four streets), Opening Night (finale), Friendship and Show Buddies (future friend-scan). Source/key award API supports box/layer/set/friend/show without duplicate external claims.
- Every fifth consecutive box without Rare-or-better forces Rare. Duplicate stars: Common 1 / Rare 3 / Super 5 / Mythical 10. Ten stars selects a missing Common/Rare in an open set. Set completion unlocks an outfit. Odds and all thresholds/copy live in content.js. Six helper bases and four equipment slots appear on hub/results/certificate, outside game scenes.
- Tower: moving crane, gravity, overlap collision, height-based sway, perfect/colour-streak bonuses, local height best. Gameplay unchanged.
- Finale placeholder `TUNIE12`; message in content.js. Certificate uses the preset nickname. Code and date checks are not security boundaries.

## Carol and character rules (all games)

Never use the musical's songs, medleys or arrangements, modern copyrighted arrangements, lyrics or recordings. Characters must not mention Jesus or teach/explain the meaning of Christmas or a carol. The existing show-day finale is exempt and unchanged. Sleigh-Cart Run retains its name.

No character, including background Tunies, wears a Santa-style red hat with white trim. Use brimmed caps, beanies, earmuffs or scarves. King Dazzlebaum wears a crown, purple coat, structured gold shoulders and gold music-note embroidery; no red robe with white fur trim. Archived gallery images remain unchanged.

## Authoring Wrap songs
`C.wrap.songs` in content.js supplies three songs in customer order. Each song has `{id, title, meter, chords, phrase, variants}`. `phrase` contains `[MIDI pitch, quarter-note duration]` pairs (pitch 0 = rest). `chords` contains one low-register MIDI triad per measure; `meter` is the number of quarter beats per measure. Harmony must never double the melody as an independent line. Only verified public-domain melodies with recorded provenance may be used; no modern recording, arrangement or lyrics.

The content module derives each variant `{duration, beat, events, automatic}` in milliseconds from the same complete phrase. `events` are sorted `{time, lane, midi}` objects. Time zero is the first hit arrival after existing visual travel. Lane 0/1/2/3 means Fold/Tape/Ribbon/Bow. Easy charts notes at least 1500 ms apart on two lanes, putting only omitted melody notes in `automatic` (quiet harp fills). Tunie charts the whole melody; Rapper charts it faster with occasional simultaneous octave pairs on different lanes. Keep same-lane arrivals more than two judgement windows apart. Pitch belongs to the event, so missing does not shift the tune. A weekly `content.wrap.songs` override replaces the songs through the existing content mechanism; provide fully resolved variants when overriding. `automatic` may be omitted on literal charts (defaults to no fills).

The backing scheduler uses half-beat steps, scheduling 350 ms plus reported latency ahead. Negative steps -6/-4/-2 are the three count-in clicks; nonnegative steps play bass, chord stabs, pad and kit. Automatic fills have a separate cursor. Neither cursor advances from taps. No full-song recording needs downloading or synchronizing. Keep total new music assets under ~2 MB and fetch only inside Wrap. Source samples are mono PCM16 at 22050 Hz, trimmed/faded and peak normalized to -1 dB; sources.json pins the upstream commit and individual source files. Root MIDI values refer to measured sounding pitches, since source octave naming varies. Playback chooses the nearest root and transposes using playbackRate. Generated pad/kit sounds and original non-Wrap cues require no files.

Run `npm test` after chart/audio changes. Checks cover complete melody preservation, Easy fills, spacing, bank size/provenance, all nine legal charts, perfect runs and backing separation. Browser checks cover Chrome/WebKit journeys, touch/keyboard, mute/resume, loading failure, lazy requests, count-in, distinct decoded instrument buffers and an OfflineAudioContext mix render (audible backing, melody RMS above backing, no clipping). Physical phone listening remains required for recognisability, speaker balance, silent switch and output timing.

## Environment
Runtime needs no npm installation. `npm run build` hashes game source files and packaging templates/config, generates docs/build.json, docs/404.html, docs/sw.js, the root index and a complete immutable docs/releases/<id>/ snapshot. Only game runtime and source-credit files enter each release (about 0.84 MB), under the 3,000,000-byte gate in scripts/build-config.json. docs/releases.json records newest-first order; each build keeps current plus the previous two slim releases and removes older folders. Open older tabs retain their complete local worker cache until a safe update, even if their host folder was pruned. Gallery and review artifacts stay ordinary unversioned review pages, outside release hashes and precaches. Do not hand-edit generated files. `npm run build:check` and the Node tests reject stale generated output, modified release files or mismatched ids. `npm run dev` generates the release and serves docs/ on port 4173. `npm install` installs test tools only. `npm test` runs Node checks. `npm run test:browser` runs headless installed Chrome with phone emulation. To include WebKit, install its Playwright browser and set TUNEVILLE_WEBKIT=1 (plus PLAYWRIGHT_BROWSERS_PATH if installed in a custom cache). Tests reuse or start a local server. Emulation is not physical iPhone/Android/iPad certification.

## Deployment update checks
`game/update-check.js` discovers the published id on open, visibility return and every `C.update.interval` (300000 ms) while visible. Review strips show the running 20-character content hash. A unique missing `.update-check/<uuid>` path reads the id from the custom 404, bypassing query-insensitive CDN keys on GitHub Pages. Plain-404 hosts fall back to no-store build.json and must honor revalidation; custom-404 support is preferred. Positive Age responses fail silently. No third-party service is involved.

Only hub, Wrap/Sorting/Tower setup, collection and gift screens allow automatic reload, with no modal, text editing or hidden tab. Play, pause, practice, between-song screens, all results, unwrap and finale are excluded. The target’s immutable manifest and file hashes are verified into a separate cache before the 1.6-second content-owned note. Safety is checked again, save/trusted time are persisted, and the target’s immutable entry loads then restores the root query/hash. A session-storage guard permits at most one automatic navigation per target per tab session. Offline/incomplete deploys retry on later checks. Suspended tabs have no update deadline until visible; then download time and a safe screen determine the delay.

## Sleigh-Cart Run (game 4)
`game/sleigh.js` is the pure runner; `sleigh-art.js` shares object SVGs across the canvas, cards and Road guide; `sleigh-ui.js` owns portrait rendering, pointer/Space/Up, hold/double hop, paused cards, background handling and cues. All copy and tuning belong to `C.sleigh`. Slot 4 retains the Dec 4 trusted-clock gate; review mode alone opens early and offers stages 1–8.

Revision 3 phone follow-up: tap impulse 370/gravity 1150 peaks at 58.75 and lands in 0.642 s. Hold lift begins only after 140 ms, so quick presses through 130 ms produce identical low hops. Hold/double peak 130.23/145.10 with 1.075/1.175 s flights; only these clear snowman 100. Tap stays below roofs 125. Low fence/toboggan collision judges the cart centre against the full visible obstacle width, allowing trailing wheels to settle; clearance is 32/20 respectively. Other hazards retain the 44-unit cart footprint. Seven lessons separately introduce fence, gift, door, garland, pothole, toboggan and snowman; each has two successful encounters followed by an 18-second learned-elements play stretch. Stage 8 unlocks content-owned named patterns, tighter spacing, rising speed/warning pressure and bar-aligned music tempo. Street names, ground palette and house arrangement follow stages.

The cart starts with six gifts, capped at eight. Hits clear incoming hazards and postpone new spawns through the catch/landing relief; garland catches require staying grounded. Hits after 420 active seconds knock off up to three gifts, with one catchable. Landing on a gold step spends one gift and increments delivered count. Step width is approach speed × stage deliveryWindow (0.30→0.18 s). Only centre-on-step landings deliver; rolling never does. The take-off road line fades across four deliveries. Early/late/rolling misses give distinct feedback and consume no gift. Middle 34% landings earn a 50-point bonus and larger sparkle; bonus total appears in results without changing the delivered-count record or medals. Practice must finish with a landed delivery.

`recordSleigh` supplies the Treasure Book boundary, reporting delivered, perfect/bonusPoints, distance, medal, wonLayer, best, personalBest, celebration and cause. Bronze/Silver/Gold remain 4/10/20; Tissue is awarded only for Bronze. The shared completion handler queues boxes, unlocks medal outfits and adds Pip with Tissue; normalized old saves already holding Tissue also receive Pip. Existing optional sleighBest/sleighPlayed/sleighPractice fields default safely; Tower best is only a numbered pennant. Shared game-feedback/results-feedback preserve Sorting gameplay and the existing results flourish/confetti.

The verified traditional Go, Tell It on the Mountain chorus in sleigh-music.js uses the parameterized Sorting scheduler and existing CC0 bank, with no new runtime audio binaries. No wheel rumble, bells or chimes. Music/cues respect mute, pause, cards, background and navigation. Reduced motion suppresses optional parallax/wobble/squash/toss/confetti.

At 200,000 world units or 570 active seconds (whichever comes first), the numerical ceiling switches to 80 ms warning and incompatible snowman/garland arrivals every 10 ms: snowman needs height 100, while even an empty cart/Pip requires height ≤46 under garlands. Their collision spans overlap. Recovery stays clear; ceiling catches move at road speed so automatic catch recycling cannot prolong the run. The run ends through empty-cart collisions, never a timer.

Twenty human-style seeded simulations wait 250 ms ±100 ms after seeing hazards, vary hop timing and delivery timing ±100 ms: median Bronze 99.66 s, Silver 216.78 s, Gold 375.07 s (20/20), run end 473.00 s; aggregate door hit rate 93.67%. Full timelines, windows and phone checklist: docs/sleigh-revision-3-calibration.md and docs/review/sleigh-calibration.json. New play stretches supersede Revision 2's first-garland-at-30-second target. Physical-phone feel/audio and child calibration remain human acceptance.
