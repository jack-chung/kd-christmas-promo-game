# Technical Plan

## Architecture
Buildless front-end mobile game: native ES modules, HTML/CSS, original SVG pixel sprites, Canvas 2D Tower, and lazy-loaded CC0 sampled Wrap/Sorting instruments and original Web Audio accompaniment. No runtime dependencies, server, accounts, analytics, cookies, CDN fonts, or network saves. GitHub Pages serves `main:/docs`: an unannounced public review preview, not the campaign launch.

## Key Components
- `docs/index.html`: game entry; game title and copy come from the content module.
- `docs/game/content.js`: **all player-facing copy and character names**, preset identities, game release dates, difficulty settings, placeholder finale code/message.
- `docs/game/engine.js`: save schema/validation, date gates, grading/timing, stacking collision rules; no DOM.
- `docs/game/sorting.js`: pure endless sorting engine; stages, overrides, queue, scoring and medals.
- `docs/game/sorting-ui.js`: portrait sorting room, cards, pause and pointer/number-key input.
- `docs/game/sorting-feedback.js`: immediate sampled mid/high sack cues, generated comic effects, combo/stage echoes and tiered results flourish.
- `docs/game/sorting-music.js`: dynamically imported complete public-domain carol score, three verse textures and a separate duckable sampled band sharing the existing audio bank/context.
- `docs/game/rhythm.js`: pure lane/timing judgement, penalties, combos and customer grades.
- `docs/game/music.js`: lazy CC0 sample bank, sampled lane instruments, original bass/chord/kit/pad backing and output-latency-aware scheduling. `docs/game/audio/` holds the bank, pinned sources, full CC0 licence and reachable credits.
- `docs/game/app.js`: guarded hash navigation, screens, input, saves, review controls, game loops, audio lifecycle, pause/resume.
- `docs/game/art.js`: original integer-grid SVG sprites, hub houses, gift. No licensed assets.
- `docs/game/style.css`: portrait-first UI, pixel presentation, reduced motion.
- `docs/art-direction/index.html`: preserved comparison gallery.
- `docs/art-direction/assets/`: nine original portrait PNG screen mock-ups.
- `docs/art-direction/prompts.md`: common character/constraint brief plus each image's style and screen brief, generated with the built-in image_gen tool.
- `docs/art-direction/style-sheet.html`: selected cozy pixel palette, outline/grid rules, helper + two customers, supporting cast, production limits.
- `tests/engine.test.js`: date boundaries, save resilience, timing, stacking checks.
- `tests/browser/adventure.spec.js`: full game journeys, review/date guards, persistence, mobile/tablet layouts.

## Conventions
Cozy pixel art selected by user November 3, 2026. Preserve the red-cap apron wrapper, green-beanie glasses kid, sunglasses King, singers, and note-creature Tunies. Use original small sprites rather than concept-image crops. No licensed artwork, lyrics, script passages, or prohibited story spoilers. Names and text live in content.js.

## State and privacy
`tuneville-gift-v1` localStorage holds schema v2: preset profile, earned slot IDs, paper, sound, Wrap/Tower bests, per-difficulty Sorting bests, Sorting practice completion, shared postmark paper IDs and finale completion. Older schemas reset safely. `tuneville-host-time-v1` stores the latest verified instant. No typed names, tracking or network saves. Storage failure leaves an in-memory game. Review mode is explicit `?review=1`; preview screens never award layers.

## Dates and availability
`C.episodes` in content.js defines four ordered game slots: Wrap Nov 13, Sorting Office Nov 20, Tower Nov 27, Sleigh-Cart Run Dec 4, all at Toronto midnight (05:00 UTC). Open games stay open. Locked and unbuilt hub cards/house links are disabled, dimmed and have no card arrow; blocked direct game URLs return to the hub. Each slot’s cast selects its distinct card host. Open cards show “Not played yet” until their layer records a completed run, including zero-score runs; then they show the saved best. Unbuilt slots stay coming soon even in review mode. Finale remains Dec 12, 2026 at 4 PM Toronto (`2026-12-12T21:00:00Z`). Countdown targets the next slot date, then finale.

`trusted-clock.js` fetches a unique same-origin HEAD path with cache:no-store (query strings alone do not bypass every CDN). An intentional missing path returns 404 with the host’s current Date header; no response body is downloaded. It validates the response Date and rejects positive Age. No third-party requests or device wall clock. performance.now advances from the server anchor; visibility return and online events recheck the host. Hiding/offline freezes the last observed verified instant. Reloads retain that instant, but offline elapsed time cannot open future gates. All game and finale date checks use this clock. A failed initial check leaves date gates closed with a connection note. Static frontend checks deter device-date changes, but developer tools can modify code/storage; withholding game code until release would require a different publication system.

`docs/sw.js` caches the shell for offline reloads after the first successful visit. Host clock HEAD probes always use the network. Audio remains lazy and is cached when played; uncached audio failures leave visual play available.

## Game rules
- Wrap: 3 customers × 41–48-second public-domain carols, plus a falling-object lead-in. Four lanes in Fold/Tape/Ribbon/Bow order. Easy uses Fold/Tape at least 1500 ms apart, Tunie uses four lanes, and Rapper speeds up the same melody with occasional two-lane octave pairs. Quarter-note beats are 750 ms (Easy/Tunie) or 650 ms (Rapper); melody rhythms include half beats. Windows are ±360/300/250 ms; perfect windows ±145/120/100 ms. Pointerdown handles each thumb independently; desktop D/F/J/K and Left/Down/Up/Right keys mirror the buttons. Wrong lanes consume one nearby object; empty/wrong taps break combos and deduct score and accuracy. Missing never ends the song. Free instrument play leads to four slow, retrying guided shapes.
- Sound: successful Wrap taps play chart MIDI pitches through real recorded marimba (Fold), pizzicato strings (Tape), harp (Ribbon), and glockenspiel (Bow). Missed chart notes stay silent. Easy quietly fills only uncharted notes; Tunie/Rapper have no automatic melody. Deck the Halls, O Christmas Tree and Up on the Housetop use public-domain melodies, with our own sampled bass/chord accompaniment and generated kit/warm pad. O Christmas Tree is arranged in common time. The 642,224-byte PCM bank is fetched/decoded only on entering Wrap or Sorting Office (including direct practice/play links), with a friendly non-blocking loading/failure message. Bank failure leaves visual play available. Sound credits/source paths/licence are in game/audio/. Other game cues retain original synthesis. Wrap samples run through conservative gains and a compressor; melody sits above backing. Visual and judgement clocks share performance.now(). Backing/fill/count-in attacks compensate measured getOutputTimestamp latency or baseLatency + outputLatency. Hit sounds start immediately on pointerdown; unavoidable hardware/Bluetooth delay still requires physical-phone assessment. Three count-in clicks/visible numbers fit inside existing travel lead-in, ending at time zero. Audio unlocks on gestures and stops on pause/navigation/backgrounding; resume resets both backing and fill cursors so cancelled scheduled notes can be rescheduled. Sound is optional; all gameplay is visual. Wrap/Tower pause on hiding and require explicit resume.
- Each completed Wrap run awards paper (slot 1); each Tower run, even a zero-height tumble, awards box (slot 3). No score threshold. Rewards are idempotent; best scores can improve on replays.
- Tower: moving crane, gravity, overlap collision, height-based sway, perfect/colour-streak bonuses, local height best. Gameplay unchanged.
- Finale placeholder `TUNIE12`; message in content.js. Certificate uses the preset nickname. Code and date checks are not security boundaries.

## Adding a built game to a slot
Keep slot IDs stable. Each content slot supplies game route, title, cast, absolute Toronto release instant, label, ready flag and optional keepsake overrides. Register a new game's screens and completion handler in app.js, use the slot gate for direct links and rewards, then set ready:true. Never set ready for an unimplemented route. Slots 2–4 have explicitly marked placeholder keepsakes for leadership; slot 1 keeps its original wording.

## Authoring Wrap songs
`C.wrap.songs` in content.js supplies three songs in customer order. Each song has `{id, title, meter, chords, phrase, variants}`. `phrase` contains `[MIDI pitch, quarter-note duration]` pairs (pitch 0 = rest). `chords` contains one low-register MIDI triad per measure; `meter` is the number of quarter beats per measure. Harmony must never double the melody as an independent line. Only verified public-domain melodies with recorded provenance may be used; no modern recording, arrangement or lyrics.

The content module derives each variant `{duration, beat, events, automatic}` in milliseconds from the same complete phrase. `events` are sorted `{time, lane, midi}` objects. Time zero is the first hit arrival after existing visual travel. Lane 0/1/2/3 means Fold/Tape/Ribbon/Bow. Easy charts notes at least 1500 ms apart on two lanes, putting only omitted melody notes in `automatic` (quiet harp fills). Tunie charts the whole melody; Rapper charts it faster with occasional simultaneous octave pairs on different lanes. Keep same-lane arrivals more than two judgement windows apart. Pitch belongs to the event, so missing does not shift the tune. A weekly `content.wrap.songs` override replaces the songs through the existing content mechanism; provide fully resolved variants when overriding. `automatic` may be omitted on literal charts (defaults to no fills).

The backing scheduler uses half-beat steps, scheduling 350 ms plus reported latency ahead. Negative steps -6/-4/-2 are the three count-in clicks; nonnegative steps play bass, chord stabs, pad and kit. Automatic fills have a separate cursor. Neither cursor advances from taps. No full-song recording needs downloading or synchronizing. Keep total new music assets under ~2 MB and fetch only inside Wrap. Source samples are mono PCM16 at 22050 Hz, trimmed/faded and peak normalized to -1 dB; sources.json pins the upstream commit and individual source files. Root MIDI values refer to measured sounding pitches, since source octave naming varies. Playback chooses the nearest root and transposes using playbackRate. Generated pad/kit sounds and original non-Wrap cues require no files.

Run `npm test` after chart/audio changes. Checks cover complete melody preservation, Easy fills, spacing, bank size/provenance, all nine legal charts, perfect runs and backing separation. Browser checks cover Chrome/WebKit journeys, touch/keyboard, mute/resume, loading failure, lazy requests, count-in, distinct decoded instrument buffers and an OfflineAudioContext mix render (audible backing, melody RMS above backing, no clipping). Physical phone listening remains required for recognisability, speaker balance, silent switch and output timing.

## Environment
Runtime needs no npm installation or build. `npm run dev` serves docs/ on port 4173. `npm install` installs test tools only. `npm test` runs Node checks. `npm run test:browser` runs headless installed Chrome with phone emulation. To include WebKit, install its Playwright browser and set TUNEVILLE_WEBKIT=1 (plus PLAYWRIGHT_BROWSERS_PATH if installed in a custom cache). Tests reuse or start a local server. Emulation is not physical iPhone/Android/iPad certification.

## Sorting Office
Slot 2 uses the existing Nov 20 trusted-clock gate. `C.sorting` holds all copy, stages, arrival milliseconds, gifts per promotion, difficulty starting stages/climb multipliers, decree pool, queue capacity, warm-up timing, mistake relief, scoring and medal thresholds. Stage 2 expands from three to four streets at `fourAfter`; royal stages use three streets plus Fragile and Royal so there are never more than five targets. Fragile wins over Royal, then street. Every new stage/decree and the fourth street pauses for an icon card; no game time passes during cards, manual pause or backgrounding. Decrees rotate at the content interval; shuffle rotates target order. Stage 8+ repeats the last rules while arrival speeds climb toward the configured floor.

Three correct practice sorts complete the first-visit tutorial; wrong practice inputs retry and gifts never overflow. Each genuine five-oops run immediately awards Ribbon idempotently, updates the difficulty’s best and unlocks up to three postmark papers at difficulty-specific thresholds. Papers are shared with the existing gift renderer and collection. Save schema remains v2; missing sorting fields default safely. Review setup offers stages 1–8; ordinary setup has no picker. Sack landings use distinct sampled G-major marimba attacks (392–659 Hz) plus octave harp sparkle and a generated woody pop; wrong taps get a comic spring, and overflow a paper rasp. Combo echoes use harp/strings and promotions use strings. Every result has confetti and a 2.8–3.4-second sampled flourish; records add harmony and medals add a high answering phrase with visible stamps. Quick-bonus bars, labelled point popups and a capped ×1–×5 HUD expose the unchanged formula. The results break the total into base, quick, rush and streak points. Setup/results show each difficulty’s record; the hub shows the maximum with its difficulty. Legacy unattributed Sorting bests reset in the new per-difficulty map while other save fields survive. These cues sit over a complete Good King Wenceslas arrangement. The dynamically imported score uses marimba/harp melody, pizzicato strings/contrabass and original generated kit/pad, sharing the existing 642,224-byte CC0 bank with Wrap; no new binary audio. Its 17 bars cycle through three textures (about 109 seconds at stage 1); bar-boundary tempo rises 112→132 BPM by 2 per stage. `C.sorting.music` holds tempo and player copy. A separate band bus ducks on cards/manual pause and briefly at stage promotion; backgrounding suspends until explicit resume, and mute/navigation stop it. Bank/score requests are absent from the initial hub; the service worker caches them only after use. Failure preserves visual sorting. Provenance/credits are in game/audio/. Gameplay is independent of the audio clock. Physical phone listening remains human review; difficulty was accepted with Revision 1.
