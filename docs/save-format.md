# Portable save format

New backups use `TV2-<base64url binary>-<seven character checksum>`. The checksum is the existing FNV-1a corruption check; this is a local, transferable save, not authentication. The reader still accepts both original 21-field and extended 22-field JSON TV1 backups.

`game/save-binary.js` defines frozen wire dictionaries independent of presentation order. Do not reorder or insert dictionary IDs, or change field widths/order within TV2; incompatible additions need a new version. The card/outfit/song dictionaries describe the current complete campaign. Future content requires an explicit format revision rather than silently omitting it.

Bits run most significant first; unused trailing bits are zero. Nonnegative safe integers use unsigned base-128 varints, including millisecond timestamps without truncation. Strings use varint byte lengths and UTF-8. Counts are bounded and the reader rejects truncation, overflow, invalid indices, speeds and trailing data.

The field order is profile (3/3/7/3 bits), four layer flags, five game flags, four game bests, three retired Sorting best slots (new writers emit zero; readers merge old values into the single Sorting best), and twelve optional song records. Each song uses one presence bit, varint score, two-bit C/B/A/S grade and six-bit top speed in hundredths above 1.00. Gameplay produces steps of .05 through 1.40. Next are 33 three-bit card provenance IDs (zero absent), 17 outfit ownership flags, an optional earned-order index list, and four five-bit equipment indices. Remaining collection fields are stars, Rare counter, started time, completed-run count, Home Screen reminder time, welcome flag, queued two-bit box qualities, own friend code, friend list, new-friend list, brought-by code and reward claims.

Twenty-character uppercase hexadecimal friend codes use ten bytes plus one format bit. Other previously valid codes keep their UTF-8 spelling. New-friend entries reference the friend list where possible, preserving order and allowing standalone legacy entries. The four normal game-completion claims use three-bit IDs; arbitrary external claims retain their exact strings and idempotency. Outfit earned order and queued box reveal order survive.

The high-score full-campaign fixture in `tests/fixtures/full-save.js` has all 33 cards with varied sources, all 17 outfits, four equipped pieces, twelve 999,999-point Gold song records, all game records/flags, four layers, finale, ten boxes, 9,999 stars, 999 finished games and full timestamps. Its production restore URL is 242 characters, with 126 binary bytes and a 61×61-module M-correction QR. The 450-character budget allows 282 binary bytes: 156 remain for friends and metadata (208 URL characters). Ten permanent friend IDs, three new-friend references and a brought-by code fit inside the budget and have a round-trip regression test. Arbitrarily long friend/claim/box histories are preserved; the campaign budget is not a cap or truncation rule.

Backup QR containers use an integer number of CSS pixels per module, including the four-module quiet zone. The full-campaign QR is 207 CSS pixels wide (three per module) on both requested phones. `docs/review/wrap-backup-decode.json` records independent ZXing and Apple Vision results from the native-size screenshots; both payloads must exactly match the encoded production restore URL.
